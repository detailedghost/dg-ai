[ADR 0049](../../docs/adr/0049-jobs.md)

- Use one noun, the job. Store each job as one entry in the `jobs` table of the daemon config file, with exactly one mode key: `continuous`, `schedule` (a `cron` expression) or `every` (an interval).
- Start every run of every mode through the one launcher (`pkg/dg-daemon/src/jobs/launcher.ts`) with the same environment: allowlist, `passEnv`, `envFile`, injected keys, state folder and grant keys.
- Reach both modes from the service API routes through `JobControl`.
- Keep the verbs `add`, `update`, `remove`, `enable`, `disable`, `start`, `stop`, `restart`, `list`, `status`, `logs` and `setup`. Make `enable` and `disable` change the stored state and act now. Make `start`, `stop` and `restart` act now only.
- Stop a continuous job that exits with 0. Restart it on any other exit with a backoff of 1 s to 60 s.
- Give a failed scheduled run no second try. Skip a run that overlaps the next scheduled time. Run one catch-up after downtime.
- Never clamp an explicit `--timeout`. With `--feed` and no `--timeout`, apply the 30 s limit and the 256 KB output limit. With no `--feed`, apply no default limit.
- Print one JSON object per item for a `--feed` job. Write the output of a job with no `--feed` to its log.
- Run both migrations at each daemon start under the config lock, in `cmdServe`. Keep `config.json.pre-jobs` with mode 0600.
- Move a `scheduled_jobs` row in three steps: save the chosen name, write the config file once, then set `moved_at` and rewrite the row argv as `[]`. Run the last step with `PRAGMA secure_delete=ON` and `PRAGMA wal_checkpoint(TRUNCATE)`.
- Write `jobsVersion: 2` only on the row move.
- Keep the aliases `--label`, `--cron`, `--pass-env`, `job rm`, `job run`, `job exec` and the `dg-daemon service` group until the next major release. Make `add` with `--label` or `--cron` write an enabled job with `feed: true`.
- Keep the log path `<log>/service-<name>.log`, the pid path `<state>/daemon/services/<name>.pid` and the `SERVICE` names (`DG_SERVICE_API`, `DG_SERVICE_LABEL`, `DG_SERVICE_STATE_DIR`).
- Make `dg-daemon autostart` own the login unit. Ask once about it on the first `dg job enable` at a terminal. Print only the hint with no terminal.
- Never answer the login unit question of `job enable` from the jobs skill.
