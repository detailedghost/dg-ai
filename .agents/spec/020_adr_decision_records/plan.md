# Decision records tool (/dg:adr + dg-skills adr)

## Purpose
Split decision records into two paired files: a simple human ADR in docs/adr with a Mermaid diagram at a set reading level, and a terse agent decision in .agents/decisions with covers globs and a generated index. A new dg-skills adr CLI does the numbering, scaffolding, indexing, linting and lookup; a new /dg:adr skill owns the rules and can explain a feature at a chosen level. /dg:grill-me, /dg:spec, /dg:sdlc and /dg:land use it, so agents read only the decisions for the files they touch and update both records after a build.

## Scope
### Included
- dg-skills adr verbs: init, new, index, lint, relevant, find
- Reading levels eli5 (grade <=4), high-school (<=10, default), college (<=14), phd/technical (no grade limit); repo default in .agents/decisions/README.md frontmatter, per-ADR Level: override; the level is stored as typed
- Every new ADR gets a paired decision file with the same number and slug; a decision with no agent rules says so in one line
- Every human ADR carries a `Topic:` header line beside Status, Date and Level; `adr new` takes `--topic <t>`
- Decision files carry covers: globs in frontmatter; .agents/decisions/README.md (table with a Topic column) and docs/adr/toc.md (grouped by Topic) are generated by adr index below a marker
- adr lint: Mermaid present, reading grade, required sections, Status, Date and Topic lines, matching pair, working links, current indexes, no duplicate number; --changed (default in land), --all, and --grade <file|-> for one arbitrary text
- /dg:adr skill with write and ask modes (ask: explain a feature from ADRs at --level, self-checked with adr lint --grade)
- The three-gate test moves fully into /dg:adr; grill-me keeps a one-line pointer; fix the grill-me either/or root and the spec grill.md wrong root; agent-seed, spring-break and contributing.md point to /dg:adr
- Build wiring: sdlc slice agents read adr relevant before building; the docs step updates existing pairs and emits RATIFY for a proposed new pair; land runs adr lint --changed before merge only in repos that ran adr init
- Hoist generic frontmatter helpers from spec/frontmatter.ts to src/utils/frontmatter.ts
- A follow-up brief for bundle 021: dg-ai opt-in plus backfill of all 49 numbered ADRs (see `## Follow-up: 021_adr_backfill brief`)
### Excluded
- A CI job for adr lint in each repo
- adr init or backfill in other repos (Velora, Freebird); they opt in later with /dg:adr
- A backfill CLI verb; spring-break and agents write missing decision files
- A seventh verb; grading one text is `adr lint --grade`
- Hoisting the readability function to pkg/common
- Mermaid syntax validation in lint
- The dg-ai backfill itself; it ships as bundle 021 after this PR merges

## Code Structure

### Frontmatter helpers
- **Decision:** `splitDocument`, `parseYaml`, `scalarField`, `nestedScalar` and `records` live in `src/utils/frontmatter.ts`; `spec/frontmatter.ts` and `spec/shared.ts` re-export them.
- **Home:** `pkg/skills-cli/src/utils/frontmatter.ts`
- **Rationale:** utils must not import from a feature module, and re-export keeps every importer unchanged.
- **Alternatives:** import `records` from `spec/shared.ts` (inverts layering); copy `records` locally (duplicates a shared helper).
- **Applies to:** slices 1, 2

### adr module layout
- **Decision:** `src/adr/{index,levels,templates,paths,records,index-gen,relevant,find,lint,readability}.ts`; `index.ts` exports `HANDLERS`; `commands/adr.ts` is the lazy raw entry registered in `register-all.ts`.
- **Home:** `pkg/skills-cli/src/adr/**`, `pkg/skills-cli/src/commands/adr.ts`
- **Rationale:** matches the `spec/` sibling split, and `completion/describe.ts` reads the verbs from `HANDLERS.keys()` as it does for spec.
- **Alternatives:** one `adr.ts` file (too large for ten concerns); verbs listed by hand in `describe.ts` (drifts).
- **Applies to:** slices 1, 2

### Levels
- **Decision:** `LEVELS`, `gradeLimit()` and `parseLevel()` live in `src/adr/levels.ts`; the level is stored as typed; README key `level:`; ADR header line `Level:`.
- **Home:** `pkg/skills-cli/src/adr/levels.ts`
- **Rationale:** slices 2 and 3 import or test against one map, and no alias normalization code is needed.
- **Alternatives:** normalize `phd` to `technical` (extra code, same limit); a second map in lint (drift).
- **Applies to:** slices 1, 2, 3

### Templates and sections
- **Decision:** `HUMAN_TEMPLATE`, `AGENT_TEMPLATE`, `HUMAN_SECTIONS` and `TOC_MARKER` are string constants in `src/adr/templates.ts`; no repo-side `template.md`.
- **Home:** `pkg/skills-cli/src/adr/templates.ts`
- **Rationale:** lint, the skill reference and `adr new` must agree heading for heading, and a repo file can be edited out of sync.
- **Alternatives:** read `docs/adr/template.md` at runtime (three templates already disagree today).
- **Applies to:** slices 1, 2, 3

### Record header lines
- **Decision:** a human ADR header block carries `Status:`, `Date:`, `Topic:` and an optional `Level:`; a decision carries frontmatter `covers:` and a relative link line to its ADR.
- **Home:** `docs/adr/NNNN-slug.md`, `.agents/decisions/NNNN-slug.md`
- **Rationale:** lint rules, index grouping and the skill text all read these exact keys.
- **Alternatives:** ADR frontmatter for Topic and Level (existing ADRs use header lines, not frontmatter).
- **Applies to:** slices 1, 2, 3, 4

### Opt-in predicate
- **Decision:** a repo is opted in when `.agents/decisions/README.md` exists; every CLI verb except `init` exits 2 with `adr: not initialized. Run dg-skills adr init first.` otherwise.
- **Home:** `.agents/decisions/README.md`
- **Rationale:** `adr init` writes it, it carries the level, and skill text can test for a file without running the CLI.
- **Alternatives:** test for `.agents/decisions/` (dg-ai has that directory today and must stay opted out until bundle 021).
- **Applies to:** slices 1, 3, 4

### Exit codes and output shapes
- **Decision:** exit 0 success, 1 lint findings, 2 usage or not initialized; `relevant --json` is `[{number,title,path,adrPath}]`; `lint --json` is `[{file,rule,message,grade?,limit?}]`; the human lint line is `<file>: <rule>: <message>`.
- **Home:** `pkg/skills-cli/src/adr/relevant.ts`, `pkg/skills-cli/src/adr/lint.ts`
- **Rationale:** sdlc and land script against these shapes, and rule ids are stable strings.
- **Alternatives:** free-form messages (land could not route them to `/dg:address -l`).
- **Applies to:** slices 1, 2, 4

### Record API
- **Decision:** `loadRecords`, `repoLevel`, `matchCovers` (`records.ts`) and `renderIndexes` (`index-gen.ts`) are the only record API; lint reuses them and parses nothing itself.
- **Home:** `pkg/skills-cli/src/adr/records.ts`, `pkg/skills-cli/src/adr/index-gen.ts`
- **Rationale:** `stale-index` must compare the same bytes that `adr index` writes.
- **Alternatives:** lint re-reads files with its own parser (drift between index and lint).
- **Applies to:** slices 1, 2

### Test homes
- **Decision:** `pkg/skills-cli/__tests__/adr-fixtures.ts` builds the temp repo for every adr test; skill-text tests live in `pkg/skills-test/__tests__/adr-skill.spec.ts` (slice 3) and `adr-build-wiring.spec.ts` (slice 4).
- **Home:** the paths above
- **Rationale:** literal file paths keep the independent slices disjoint under `dg-skills spec lint-waves`.
- **Alternatives:** one shared adr spec file (slices 2 and 3 would collide).
- **Applies to:** slices 1, 2, 3, 4
