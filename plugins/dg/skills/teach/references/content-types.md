# Lessons

One self-contained HTML file per lesson. Requirements:
- **Beautiful** — clean, readable typography. Think Tufte.
- **Short** — completable quickly. One tangible win per lesson.
- **Grounded** — directly tied to the mission, in the user's ZPD.
- **Cited** — littered with links to external resources backing up every claim.
- **Connected** — HTML anchors linking to other lessons and reference documents.
- **Prompted** — includes a reminder to ask the agent follow-up questions.
- **Sourced** — recommends one primary source (most high-quality resource found).

Open the lesson file for the user via CLI command after writing it.

### Knowledge in Lessons

Teach only the knowledge required to acquire the target skill. Cover knowledge first, then practice. For knowledge acquisition, difficulty is the enemy — it eats working memory.

### Skills in Lessons

For skill acquisition, difficulty is the tool. Use:
- Interactive quizzes (answers must be equal length — don't give away the answer via formatting)
- Guided real-world step-through exercises

Build tight feedback loops — ideally automatic, always immediate.

## Reference Documents

Create alongside lessons. They are the compressed essence — designed to be revisited, not the lesson itself. Lessons are rarely re-read; reference docs are.

Good candidates: syntax/code snippets, algorithms, yoga poses, fitness routines, glossaries.

**Glossaries are essential.** Once created, adhere to the glossary terminology in every lesson. See [GLOSSARY-FORMAT.md](./GLOSSARY-FORMAT.md).

## Acquiring Wisdom

When a question requires real-world experience rather than knowledge, attempt an answer but delegate to a community. Find high-reputation communities. Respect if the user opts out.
