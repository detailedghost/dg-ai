# Hooks

`dg-skills hooks` runs small checks around tool calls in Claude, Codex, and
opencode. Every hook is off by default. `dg-skills hooks enable` writes an entry
into the tool's own settings, and `disable` removes it.
[ADR 0026](adr/0026-opt-in-hooks.md) records why.

```sh
dg-skills hooks list
dg-skills hooks status
dg-skills hooks enable spelling --set locale=en-GB
dg-skills hooks disable spelling
dg-skills hooks disable --all
```

Changes take effect in new sessions. Pass `--runtime claude|codex|opencode` to
pick a runtime. Without it, the command picks every runtime whose config folder
exists.

## Hook manifest

| Id | Event | Tools | Runtimes | What it does |
| --- | --- | --- | --- | --- |
| `spelling` | PostToolUse | Edit, Write, MultiEdit | `claude`, `codex`, `opencode` | Rejects spellings from the other English locale. Setting `locale`: `en-US` or `en-GB`. |
| `format` | PostToolUse | Edit, Write, MultiEdit | `claude`, `codex`, `opencode` | Formats the edited file with the formatter installed for its type. |
| `pr-prose` | PreToolUse | Bash | `claude`, `codex`, `opencode` | Blocks a PR or MR body that does not read as plain English. |
| `pr-confirm` | PreToolUse | Bash | `claude` | Asks before a PR or MR is created. Codex reports an `ask` decision as a hook failure and runs the command anyway, so this hook is Claude only. |
| `spec-plan-lint` | PostToolUse | Edit, Write, MultiEdit | `claude`, `codex`, `opencode` | Validates a spec `plan.md` after it is written. |
| `daily-prune` | SessionStart | none | `claude`, `codex` | Once a day, removes scratch and state past TTL and merged clean worktrees. |

opencode has no session start event, so `daily-prune` is skipped there. `enable`
prints `<runtime>: skipped <id> (not supported)` for a hook a runtime cannot run.

## Where the entries go

| Runtime | File | Shape |
| --- | --- | --- |
| Claude | `~/.claude/settings.json` | `hooks.<event>[]` groups with a `matcher` and a `command` entry |
| Codex | `$CODEX_HOME/hooks.json` (default `~/.codex/hooks.json`) | Same shape as Claude. Edit hooks match `apply_patch\|Edit\|Write`. |
| opencode | `~/.config/opencode/plugins/dg-hooks.js` | A generated plugin file. `XDG_CONFIG_HOME` replaces `~/.config`. |

opencode loads `dg-hooks.js` from its `plugins` folder. It never loads a bare
package name, so `enable` and `disable` remove a stale `dg-hooks` entry from the
`plugin` list in `opencode.json`.

Each entry runs `<state>/bin/dg-skills hooks run <id>`. The state folder is
`~/.dg`, or `$DG_HOME` when set. The `locale` value lives in `config.json` in
that folder, not in the tool settings.

## The owned marker

dg owns an entry only when its whole command is a path ending in `dg-skills`,
then `hooks run`, then one hook id. The match is anchored at both ends. Your own
hooks never match, even when they mention `dg-skills`.

- `enable` adds or refreshes owned entries. It leaves every other key and entry alone.
- `disable` removes owned entries only.
- For opencode, the first line of `dg-hooks.js` is the marker
  `// generated by dg-skills hooks; do not edit`. A `dg-hooks.js` without it is
  yours. The command stops and asks you to move it aside.

## Concurrency

Other tools write the same settings files. `enable` and `disable` read the file,
change it in memory, and read it again before the write. If the file changed in
between, the command starts over, up to three times, then stops with
`kept changing; try again`. The write is an atomic rename. The command keeps the
file mode, follows a symlink to its target, and creates new files with mode
`0600`.

A file that is not valid JSON stops the command before any runtime changes.
Fix the file and run the command again.

## Uninstall

```sh
dg-skills hooks disable --all
```

This removes every owned entry from every runtime and deletes `dg-hooks.js` when
no hook is left. Then run `dg-skills doctor hooks` to confirm no stale entry
remains.

## Latency

Each hook starts a `dg-skills` process, so a hook adds delay to every tool call
it matches. The 40 ms latency budget arrives with a later change. Until then,
hooks are slower than plain shell hooks. Keep your own shell hooks if the delay
matters to you.

## Doctor

`dg-skills doctor hooks` checks that the skill files exist, that each
runtime's settings parse, that no owned entry points at a missing `dg-skills`,
and that allow rules cover `dg-skills hooks status`, `list` and `disable`.
It warns when a broader rule also allows `hooks enable`, because Claude then
stops asking before it enables a hook.
